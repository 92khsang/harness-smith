# Management Authority is separate from provenance, and mutation needs four conditions

Provenance says where an artifact's content came from; it never says who may write it now. An artifact adopted from an external seed is locally owned, and an artifact this repository generated may still be regenerated by an external tool. Management Authority is therefore its own axis: `local`, `harness-smith`, `external-plugin`, or `unknown`. It applies only where mutation is conceivable — inside repository and plugin scope. Outside those, the adapter's Capability Policy forbids mutation before authority is ever consulted, so "observed" belongs to Capability Policy and the Observed Artifact set, not to this enum.

`unknown` refuses mutation, and imported or externally generated artifacts default to it rather than inheriting authority from provenance. A Consumer alone does not change authority: an external tool reading an artifact is not evidence that anything writes it. The three cases are distinct.

- Tracked, no writer or authority evidence: `local` (presumed).
- External Consumer confirmed, no Writer evidence: still `local` (presumed), with a review warning.
- External Writer confirmed, no authority declaration: `unknown`, and an error.

## The presumption, named as one

A tracked artifact with no authority evidence is presumed `local`. This is a presumption, not a fail-closed classification, and it exists because the strict alternative turns `init` on any real repository into a wall of errors that trains people to ignore the validator. The blast radius is narrowed instead: presumed-`local` artifacts are mutated only as reviewed patches, never regenerated wholesale, and `init` lists them in a non-blocking bootstrap report.

## Mutation is a conjunction

A permissive Capability Policy is one term, not permission. Every mutation requires all four:

- the adapter's Capability Policy permits mutation for that Surface,
- Management Authority permits it,
- the invoking operation is write-capable,
- and the required review or approval is satisfied.

## Consequences

- Write and delete operations set `disable-model-invocation: true`, and the CLI independently enforces dry-run by default, `--apply` for real writes, and refusal to run without an identifiable repository root. Skill routing control is not a security boundary, because the model can invoke the CLI directly.
- Write safety is bounded and stated rather than implied: every patch is computed and validated before any write begins, a precondition failure writes nothing at all, and each file is replaced atomically. Cross-file crash atomicity is **not** guaranteed — a crash partway through a multi-file apply can leave some files written and others not. Guaranteeing it would need a transaction journal, which v1 does not implement. An interrupted apply is recoverable instead of atomic: when every change target sits at either its recorded before or after state and no observation changed beyond what the plan itself explains, re-submitting the same reviewed plan document resumes the apply and writes only what remains. Any other state is refused as stale, and the plan must be produced and reviewed again.
- Hooks inside an Artifact Container inherit the containing file's authority, and a reviewed patch is generated against that whole file's current digest. Per-section authority is not supported in v1.
- Declaring local ownership of an artifact an external tool regenerates is allowed and warned about, because it is a standing hazard rather than an error.
